# 鸿蒙(HarmonyOS 6.0)打包指南

这是「台账查找」的鸿蒙壳工程:原生 ArkTS 壳 + ArkWeb 加载 `www/` 网页(与 Android APK 同一套前端)。

- 应用包名:`com.taizhang.sim`
- 应用名称:台账查找
- 方向:横屏自动旋转(与 Android 版 sensorLandscape 一致)
- 权限:仅 `ohos.permission.INTERNET`(允许 HTTP 连接局域网服务器)

## 一、需要安装的软件

| 软件 | 说明 |
| --- | --- |
| DevEco Studio 6.0 及以上 | 华为官方 IDE,下载:https://developer.huawei.com/consumer/harmonyos/deveco-studio/ 。首次启动按提示装 HarmonyOS SDK |
| Node.js 18+ | 你电脑已有(打包工具链依赖) |
| 华为开发者账号 | https://developer.huawei.com/consumer/ 注册,真机调试和上架必需 |

## 二、修改前端后同步到鸿蒙工程

网页代码在项目根目录 `www/`,改完后执行:

```bash
npm run harmony:sync
```

会把 `www/` 复制到 `harmony/entry/src/main/resources/rawfile/www/`。

## 三、DevEco Studio 打开工程

1. 打开 DevEco Studio → File → Open → 选择本目录(`harmony` 文件夹)。
2. 首次打开会自动执行 Sync。如果提示 hvigor / SDK 版本不匹配,点提示里的 **升级/修复(Migrate)** 让 IDE 自动调整即可。
3. `compatibleSdkVersion` 当前为 `5.0.0(12)`(兼容鸿蒙 NEXT 5.0 ~ 6.0 设备);若 IDE 提示可改高,按提示确认即可,不影响功能。

## 四、签名(真机调试)

1. 平板/手机进入 **设置 → 关于本机**,连点"软件版本"开启开发者模式;再到开发人员选项里打开 **USB 调试**。
2. 数据线连电脑,设备上弹窗点"允许 USB 调试"。
3. DevEco 里 File → Project Structure → Signing Configs → 勾选 **Automatically generate signature**(自动签名),登录华为开发者账号,勾选调试证书,OK。
4. 工具栏选中你的设备,点绿色 ▶ Run,即可装机调试。

> 自动签名一次最多注册 100 台调试设备,内部使用足够。

## 五、出正式包

### 方式 A:不上架,企业内部分发(推荐先用这个)

1. AGC(AppGallery Connect)→ 证书管理:创建**发布证书** `.cer` + **发布 Profile** `.p7b`(Profile 选"发布",设备可选)。
2. 本地用 keytool/DevEco 生成 `.p12` 密钥。
3. DevEco → File → Project Structure → Signing Configs → release 配置里选好 .p12/.cer/.p7b。
4. 菜单 Build → Build App(s)/HAP(s) → **Build Hap(s)/APP(s)** → 得到 `entry/build/default/outputs/default/entry-release-signed.hap` 或 `.app`。

> 不上架的话,HarmonyOS NEXT 设备无法像安卓那样直接装 hap,需要通过 AGC 的**开放式测试/定向分发**,或申请**企业内部分发证书**(In-App distribution 需 MDM 场景)。最简单路径:AGC 创建应用 → 云端托管 → 受邀设备安装。

### 方式 B:上架华为应用市场

1. AGC → 我的项目 → 创建应用,包名填 `com.taizhang.sim`。
2. 回到 DevEco 配置发布签名,Build → Build App(s) → 输出 `.app` 包。
3. AGC 提交审核上架。

## 六、常见问题

- **登录页"后端地址"**:和平板 Android 版一样填 `http://<电脑IP>:10600`,平板和电脑需在同一局域网。后端已放开 CORS,无需改动服务器。
- **三维场景白屏**:ArkWeb 支持 WebGL,如遇问题看 Log 面板过滤 `[taizhang]`。
- **改了 www 没生效**:先跑 `npm run harmony:sync` 再在 DevEco 里重新 Run。
- **返回键**:壳内已处理——网页有历史则网页后退,否则退出应用。

## 七、命令行打包 HAP(不开 IDE,一条命令出包)

命令行打包直接使用 DevEco Studio 26.0 自带的 hvigor(`D:\STUDIO\DevEco Studio\tools\hvigor\hvigor`),电脑装有 DevEco Studio 26.0 即可出 HAP,不用打开 IDE。

1. 改过 `www/` 前端后,先同步到鸿蒙工程:

```bash
npm run harmony:sync
```

2. 在 `harmony` 目录执行(PowerShell,一条命令):

```powershell
$env:NODE_HOME='D:\STUDIO\DevEco Studio\tools\node'
$env:DEVECO_SDK_HOME='D:\STUDIO\DevEco Studio\sdk'
$env:JAVA_HOME='D:\STUDIO\DevEco Studio\jbr'
node "D:\STUDIO\DevEco Studio\tools\hvigor\hvigor\bin\hvigor.js" --mode module -p module=entry@default -p product=default -p buildMode=debug assembleHap --no-daemon
```

3. 产物:`entry\build\default\outputs\default\entry-default-unsigned.hap`(未签名,可复制到项目根 `dist\`)。

> 以上 3 个路径是本机「真 DevEco Studio」默认安装位置;换机器/装到别的盘时改成自己的路径。
> 工具链随 DevEco Studio 自带,无需额外安装依赖;换机器/装到别的盘时把命令里的 `D:\STUDIO\DevEco Studio` 改成自己的安装路径。
> 换新 SDK 版本后若报 `SDK component missing`,把 `build-profile.json5` 的 `compileSdkVersion` 改成新 SDK 版本号(见下节)。

## 八、关键构建配置(踩坑记录,升级 SDK/换机时对照)

1. **SDK 版本必须对上**:`harmony\build-profile.json5` 里 `compileSdkVersion = "26.0.0"` 是本机 DevEco 内置 SDK(API 26, DevEco 26.0)的版本号;`compatibleSdkVersion = "5.0.0(12)"` 保持不变(兼容 NEXT 5.0~6.0 设备)。编译报 `00303168 SDK component missing` = 版本字符串与本地 SDK 不匹配。
2. **ArkTS 新 API 适配**(`entry/src/main/ets/pages/Index.ets` 已按新 SDK 改好,勿回退):
   - Web 混合加载属性由 `.mixedContent(MixedMode.All)` 改名为 `.mixedMode(MixedMode.All)`;
   - 页面开始/结束事件由 `event.request.getRequestUrl()` 改为 `event.url`(事件结构在新 SDK 已简化)。
3. **命令行打包必须设 `JAVA_HOME`**:指向 DevEco 自带 JDK(`...\jbr`),否则报 `spawn java ENOENT`。
4. **未签名 HAP 不能装真机**:HarmonyOS NEXT 强制签名校验。要装机必须先在 DevEco 里配置签名再出包(见「四、签名」),或走 AGC 分发(见「五」)。
5. **IDE 同步报 `00302013 root node is not yet available`**:工程 `harmony\node_modules\` 里存在 npm 装的 `@ohos/hvigor*` 与 IDE 内置 hvigor 冲突。解决:删除工程 `harmony\node_modules\` 下所有 `@ohos` 内容,回 IDE 重新同步即可(本工程已清理,勿再 npm 安装)。

## 九、命令行打包说明

- 命令行工具链使用 DevEco Studio 26.0 内置 hvigor(`D:\STUDIO\DevEco Studio\tools\hvigor\hvigor`),工程不依赖 `node_modules`。
- `harmony\hvigorw.bat` / `hvigorw.js`:标准工程文件(IDE 自动识别)。
- 注意:不要往工程 `harmony\` 下 npm 安装 `@ohos/hvigor*` 到 `node_modules`,会与 IDE 内置 hvigor 冲突,导致 IDE 同步报 `00302013 root node is not yet available`。

## 十、鸿蒙真机"白屏 / 连不上后端"终极方案(WebSchemeHandler 代理)

### 现象与根因(已踩坑验证)

| 现象 | 根因 |
| --- | --- |
| 本地 rawfile 页面能显示,但登录/查询"无法连接服务器" | ArkWeb 内核默认禁止 `resource://` 本地页面发起跨域 fetch(即使加了 INTERNET 权限和 network_config 明文放行) |
| Web 直接加载 `http://<IP>:10600/www/` 顶层明文页面 → 白屏 | ArkWeb 顶层导航明文 http 被安全策略拦(仅对子资源放开无效) |

### 最终方案:本地页面 + WebSchemeHandler 拦截代理

页面仍用本地 `rawfile/www/`(不会白屏),页面 JS 里所有 `fetch("http://...")` 请求由鸿蒙侧 `WebSchemeHandler` 拦截,用 `@kit.NetworkKit` 的 http 模块转发到真实后端,并强制附加 `Access-Control-Allow-Origin: *` 等 CORS 头返回给页面。彻底绕开"跨域 + 明文"两道墙。

关键代码(`harmony/entry/src/main/ets/pages/Index.ets`):

```ts
import { webview, WebNetErrorList } from '@kit.ArkWeb';
import { http } from '@kit.NetworkKit';

schemeHandler: webview.WebSchemeHandler = new webview.WebSchemeHandler();

aboutToAppear(): void {
  this.schemeHandler.onRequestStart((request, resourceHandler) => {
    const url = request.getRequestUrl();
    if (!(url.startsWith('http://') || url.startsWith('https://'))) return false;
    this.forward(request, resourceHandler, url);   // 异步转发
    return true;                                    // true = 拦截
  });
}
// Web 组件 onControllerAttached 里(初始化后)设置:
//   this.controller.setWebSchemeHandler('http', this.schemeHandler);
//   this.controller.setWebSchemeHandler('https', this.schemeHandler);

// 转发核心:
// 1) request.getHeader(): Array<WebHeader>  -> 原样带到 http 请求
// 2) request.getHttpBodyStream(): 读取 POST body
//      stream.initialize().then(() => stream.read(stream.getSize()))  -> options.extraData = buf
// 3) http.createHttp().request(url, options) 转发
// 4) 构造 webview.WebSchemeHandlerResponse:
//      setNetErrorCode(WebNetErrorList.NET_OK); setStatus(200); setStatusText('OK')
//      setHeaderByName('Access-Control-Allow-Origin', '*', true)
//      setHeaderByName('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS', true)
//      setHeaderByName('Access-Control-Allow-Headers', 'Content-Type, Authorization', true)
//      setMimeType(ct); setEncoding('utf-8')
//    resourceHandler.didReceiveResponse(wr)
//    resourceHandler.didReceiveResponseBody(arrayBuffer)
//    resourceHandler.didFinish()
```

### 后端必须配合:CORS 放行 `null` origin

`resource://` 页面发出的请求 `Origin: null`,后端 FastAPI 的 `CORSMiddleware` 默认只放行内网 IP,会把 CORS 预检直接打 400。已把 `backend/app.py` 的 `_DEFAULT_ORIGIN_REGEX` 改为:

```python
_DEFAULT_ORIGIN_REGEX = r"(https?://.*|null)"
```

改完必须重打包后端 EXE 再部署(PyInstaller),否则预检仍 400、登录报 CORS。

### 验证命令(后端侧)

```powershell
# 预检:应返回 200 且 Allow-Origin: null
Invoke-WebRequest -Uri 'http://127.0.0.1:10600/api/login' -Method Options -Headers @{'Origin'='null';'Access-Control-Request-Method'='POST'} -UseBasicParsing
# 登录:应返回业务 JSON(而非 CORS 报错)
Invoke-WebRequest -Uri 'http://127.0.0.1:10600/api/login' -Method Post -ContentType 'application/json' -Headers @{'Origin'='null'} -Body '{"username":"x","password":"y"}' -UseBasicParsing
```

### 已知注意

- WebSchemeHandler 需在 Web 组件初始化后设置(onControllerAttached),否则设置失败。
- `onInterceptRequest` 无法获取 POST body,有 POST 一定要用 WebSchemeHandler。
- 本方案下页面域名始终是 `resource://rawfile/www/index.html`,无需(也不建议)再用"Web 直接加载远程页面"的方案。
